# Functional Status

_Last updated: 2026-04-26_

This document captures where the current alpha build stands versus the roadmap described in `README.md` and `ARCHITECTURE.md`. Use it to see what already works, what is partially there, and which gaps remain before we can call the heap analyzer "functionally complete".

## Snapshot
- ⚠️ **v0.3.0 release prep is in progress on this branch**: the workspace version is now `0.3.0`, the release `CHANGELOG.md` entry is curated, and the remaining M7-6 slices cover release notes, final validation, tag/push, and post-release packaging. **v0.2.0 remains the current published release until the tag is cut.**
- ✅ **M1.5 real-world hardening landed**: `HEAP_DUMP_SEGMENT` parsing now uses the correct HPROF tag constant (`0x1C`), record-tag naming matches the spec, and the workspace now validates `parse`, `analyze`, `leaks`, and `gc-path` against a real JVM heap dump when the optional `resources/test-fixtures/heap.hprof` fixture is present.
- ✅ **HPROF parser** streams headers/record stats and produces a record-category histogram + heap summary without loading entire dumps into RAM.
- ✅ **Object-graph pipeline** now lives under `core::hprof/`, where the shared object graph, binary HPROF parser, and test fixtures are grouped together for the parsing domain. `ObjectGraph` can retain raw instance `field_data`, selective `byte[]`/`char[]` contents, and parsed `STACK_TRACE` / `STACK_FRAME` records for higher-level analyzers, but that retention is now opt-in through `ParseOptions { retain_field_data: true }` so default `analyze`, `leaks`, and `gc-path` runs stay on the lean path.
- ✅ **M3 foundation tooling landed**: `core::hprof::tags` now centralizes top-level and heap-dump sub-record constants for the parser, binary parser, fixtures, and GC-path traversal, and the repository now includes Criterion bench targets plus `scripts/measure_rss.sh` for throughput/RSS baselining.
- ✅ **M3-P1-B2 core analysis features landed**: `analyze_heap()` now emits grouped histograms, unreachable-object summaries, and MAT-style suspect scoring; `diff_heaps()` now attaches class-level deltas when both dumps build object graphs; and the CLI exposes `analyze --group-by class|package|classloader` plus class-diff table output.
- ✅ **M3 Phase 2 investigation features landed**: `analyze_heap()` can now attach optional thread, string, collection, and top-instances reports; the core ships `inspect_threads()`, `analyze_strings()`, `inspect_collections()`, and `find_top_instances()`; and the CLI exposes `analyze --threads --strings --collections --top-instances` plus tuning flags `--top-n` and `--min-capacity`.
- ✅ **Step 11 large-dump scaling validation landed**: `ParseOptions` now controls field-data retention, `analyze_heap()` only opts into higher-memory parsing when string/collection/thread investigation is requested, `detect_leaks()` and `gc-path` stay lean by default, the enhanced `scripts/measure_rss.sh` profiles `parse`, `analyze`, and `leaks` with ratio markers and `/proc/PID/status` fallback sampling, and the dense synthetic validation batch now clears ~500 MB / ~1 GB / ~2 GB tiers with default-path RSS ratios around 2.87x-2.90x and investigation-path ratios around 3.89x-3.92x.
- ✅ **M7-1 streaming overview mode landed**: `AnalysisMode { auto, deep, overview }` is now shared across core, CLI, MCP, and report rendering. `core::hprof::overview` streams class-resolved top-N aggregates, GC-root counts, and capped thread-frame samples without ever building an `ObjectGraph`, `auto` flips to overview at 4 GiB by default and can be overridden with `MNEMOSYNE_OVERVIEW_AUTO_THRESHOLD`, and overview output is explicitly partial with approximate shallow sizes only, not retained sizes.
- ✅ **M7-2 CI regression policies landed**: `core::policy` now loads dedicated TOML policy files, evaluates 10 predicates (7 overview-compatible plus deep-only `leak_count`, `retained_size`, and `dominator_root_count`) against deep or overview inputs, renders text/JSON/JUnit/GitHub Actions output, and `mnemosyne-cli ci-check` ships the severity-aware exit-code contract (`0` clean, `1` violation, `2` invalid policy, `3` unreadable heap/analyze failure, `4` explicit overview-mode mismatch).
- ✅ **M7-3 allocation-site flame graphs landed**: `core::report::flamegraph` now collapses graph-backed deep analysis into dominator, class-hierarchy, or GC-root-path folded stacks and renders SVG via `inferno`, plus folded-stack text and a structured JSON envelope. `mnemosyne-cli flamegraph` is deep-mode-only, uses the new public `analyze_heap_with_graph()` entry point to access graph internals without widening `AnalyzeResponse`, and exits `5` when the user requests or auto-resolves to overview mode.
- ✅ **M7-4 OQL targeted expansion landed**: `core::query` now ships the approved six-feature MAT-parity slice end-to-end: `@retainedSize` comparisons, synthetic `@toString`, `@gcRootPath` projection/filtering, `LIKE` / `CONTAINS`, `OBJECTS` single-hop projection, and `IS NULL` / `IS NOT NULL`, plus single-quoted string literals. The query layer now reuses a shared `core::graph::gc_root_path` helper, `core::query::synth` owns synthetic string rendering, and deep-only query features map to structured `FeatureUnavailableInOverviewMode` errors when callers reuse the query engine without a deep graph.
- ✅ **CLI surface** (`parse`, `leaks`, `analyze`, `ci-check`, `flamegraph`, `diff`, `map`, `gc-path`, `query`, `explain`, `chat`, `fix`, `serve`, `config`) all call into the shared core. `parse`, `analyze`, `ci-check`, and `flamegraph` now share `--mode auto|deep|overview` resolution where appropriate; `ci-check` adds `--policy`, `--format text|json|junit|github-actions`, `--output`, and `--fail-on info|warning|error|critical`; `flamegraph` adds `--root dominator|class-hierarchy|gc-root-path`, `--format svg|folded-stack|json`, required `--output`, and exit code `5` for overview-mode mismatch; `parse` summary sections and `leaks` output render aligned terminal tables at the CLI boundary; `chat` now ships as a CLI-first leak-focused conversation mode with `/focus <leak-id>`, `/list`, `/help`, and `/exit`; and follow-up disclosure sections still appear when width-bounded cells truncate record-category names, leak IDs, or class names.
- ✅ **Query surface** now covers the targeted M7-4 OQL slice without breaking existing queries: built-in pseudo-attributes `@retainedSize`, `@toString`, and `@gcRootPath`; `LIKE` / `CONTAINS` on string-capable fields; `OBJECTS x.field`; `IS NULL` / `IS NOT NULL`; and single-quoted string literals. The shared CLI error mapping reserves exit code `6` for deep-only query features that are evaluated without a deep graph.
- ✅ **Zero-result UX** is now explicit: `mnemosyne leaks` prints `No leak suspects detected.` when analysis completes without candidates, and `mnemosyne fix` already returns `No fix suggestions available for the provided criteria.` when nothing matches the requested filters.
- ✅ **Error handling** now uses structured `CoreError` variants plus CLI `hint:` lines for missing heap dumps, wrong file types, HPROF header parse failures, and invalid config files.
- ✅ **Leak detection** is now unified: `detect_leaks()` attempts object-graph → dominator → retained-size analysis first, then falls back to heuristics with explicit `ProvenanceKind::Fallback` markers. `explain --leak-id`, `fix --leak-id`, and MCP `explain_leak` now validate the requested leak identifier up front and return `CoreError::InvalidInput` for unknown IDs instead of silently widening to the full leak set.
- ✅ **Graph/dominator view** now supports real retained sizes in both `analyze_heap()` and `detect_leaks()`, with the lightweight summary preview retained only as fallback.
- ✅ **GC path finder** now prefers full `ObjectGraph` BFS first, then falls back to a budget-limited `GcGraph`, then synthetic paths when the heap lacks enough detail.
- ✅ **Object-graph navigation API** now exposes `get_object(id)`, `get_references(id)`, and `get_referrers(id)` for programmatic heap exploration.
- ✅ **M3 completion batch is now landed and verified**: beyond the earlier M3 Phase 3 classloader/query/profile work, the branch now includes optional `hyperfine` / `heaptrack` benchmark wrappers with graceful skip behavior plus the deeper live query slice with retained instance-field projection/filtering on CLI/MCP query paths and hierarchy-aware `INSTANCEOF`.
- ✅ **M6 ecosystem, community, and UI completion landed**: the shared React frontend under `ui/` now spans the local artifact loader, triage dashboard, artifact explorer, heap explorer, and leak workspace. Heap explorer panes now resolve selected objects back to leak IDs for direct cross-navigation into the leak workspace, and the Object Inspector can load live references/referrers when a host bridge is present. The repository also now ships the new user guide, troubleshooting guide, benchmark comparison doc, CI integration guides, example projects, and expanded contributor/community guidance.
- ⚠️ **Tauri desktop shell is scaffolded, not yet a release artifact**: `tauri/` now bundles the shared `ui/` build, injects both host bridges, and exposes native commands for heap loading, query execution, references/referrers, leak explanation, GC-path lookup, source mapping, and fix suggestions. Tagged releases do not yet publish desktop bundles.
- ⚠️ **AI insights** now support three explicit modes: `rules` (default), `stub`, and `provider`. Provider mode now supports YAML-backed prompt templates through an embedded default plus optional `[ai.prompts].template_dir` overrides, plus Step `14(d)` privacy controls under `[ai.privacy]` for `heap_path` redaction, regex-based prompt redaction, opt-in hashed audit logging before external model calls, and a minimal prompt-budget guard. Step `14(e)` now ships both a CLI-first conversation slice through `mnemosyne-cli chat <heap.hprof>` with bounded in-process history and top-3 shortlist context, and persisted MCP AI sessions for resumed chat/explain/fix follow-up. `fix` / `propose_fix` now attempt an AI-backed source-aware patch path when provider mode plus mapped source context are available. MCP transport hardening now has direct `serve` coverage for delayed AI-backed responses and larger payloads, and provider failures/timeouts surface dedicated machine-readable MCP error codes. Streaming remains unnecessary on the verified branch contract.
- ✅ **Report/export** supports Text/Markdown/HTML/TOON/JSON with `--output-file`, plus `mnemosyne flamegraph` SVG/folded-stack/JSON exports through `core::report::flamegraph`. HTML output is XSS-hardened; TOON values are properly escaped; flamegraph SVG is rendered via `inferno`; provenance markers are rendered in all non-JSON analyze formats; and overview-mode renderers now lead with explicit streaming-triage banners plus honest approximate-shallow-size labeling.
- ✅ **Provenance system** labels synthetic, partial, fallback, and placeholder data across analysis responses, leak insights, GC paths, and fix suggestions. CLI and report renderers surface these markers to consumers.
- ✅ **Output hardening** — HTML escaping prevents XSS in report output; TOON escaping handles control characters and backslashes correctly.
- ✅ **Development workflow** now includes GitHub Actions CI, the `test-fixtures` cargo feature for canonical fixture reuse, real-world HPROF validation that skips gracefully when the large fixture is absent, focused wrapper coverage for `scripts/tests/test_run_hyperfine_bench.sh` and `scripts/tests/test_run_heaptrack_profile.sh`, and current full-worktree verification with 448 passing Rust tests (`cargo test`; doctests 0).
- ✅ **Release automation** now validates `v*` tags against the workspace version, cross-compiles `mnemosyne-cli` for five targets, packages archives, publishes GitHub Releases with attached binaries, and builds/pushes the GHCR Docker image on tagged releases.
- ✅ **Packaging metadata + Homebrew scaffolding** now cover crates.io-ready workspace metadata across `Cargo.toml`, `core/Cargo.toml`, and `cli/Cargo.toml`, plus a macOS Homebrew formula for both Apple Silicon and Intel release archives.

## Remaining Must-Haves Before "Functionally Complete"
Graph-backed leak detection unification, M3 investigation/query follow-through for the approved scope, regression-quality integration coverage, large-dump scaling validation, and the approved M4-M6 UI/ecosystem scope are now complete. The remaining follow-on work is narrower and evidence-driven:

1. **Richer exporters/visualizations beyond the shipped flamegraph surface** (e.g., protobuf or richer diff views) layered atop the existing JSON writer and `--output-file` plumbing.
2. **Optional desktop distribution hardening** if native packaging becomes a release requirement rather than an in-repo scaffold.

Roadmap note: M3, M4, M5, and M6 are complete for their approved milestone scopes. M7 now stands at 5/6 slices at least partially landed: M7-1 streaming overview mode, M7-2 CI regression policies, M7-3 allocation-site flame graphs, and M7-4 OQL targeted expansion are complete and verified; M7-5 is 🟡 partial (slices A/B/D done; slice C partially executed on WSL for `mnemo-overview` and `hprof-slurp` on `small`/`medium`/`large`; the native-Linux reference-spec rerun with MAT, `mnemo-deep`, equivalence, and the `10 GiB` fixture remains pending); and M7-6 is now ⚠️ in progress as the v0.3.0 release closeout, with the version bump/docs sweep underway and the tag still gated on the remaining release-prep slices.
